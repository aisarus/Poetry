# Poetry Lab — handoff для следующей ветки

**Состояние:** 9 ноября 2026. **Язык работы:** русский. **Репозиторий:** https://github.com/aisarus/Poetry, ветка `main`. Этот файл описывает актуальный технический проект, а `MEMORY_BANK.md` фиксирует отдельные вехи. Предыдущий личный handoff `POETRY_LAB_HANDOFF_FULL.md` не включён в публичный репозиторий: в нём есть неопубликованные стихи автора.

## 1. Настоящая цель

Создать **диффузионную модель, которая пишет сильную художественную поэзию на русском**, обучаясь не только на финальных стихах, но и на процессе сочинения: черновик → замечания → исправление → человеческое предпочтение. Она должна планировать всё стихотворение, сохранять удачные строки, править слабые локально, контролировать слуховые рифмы, метр, дыхание, паузы и развитие образа. **Ollama генератор → критик → редактор — baseline и потенциальный источник траекторий, не конечная модель.** Пользователь явно поправил прежний перекос в сторону анализатора; центральная работа теперь — обучение и честная оценка диффузии.

Критерии стихотворения из исходного обсуждения: минимум пять четверостиший, три соразмерные по **ударному рисунку** длинные строки и короткая четвёртая как смысловой панч (до 4–5 слогов); менять схемы ABBA/ABAB/AABB без насилия над звучанием; слуховая рифма, ассонансы, аллитерации и внутренние рифмы. Метафоры должны быть мотивированы сценой, причинностью или идеей; избегать случайного набора красивых слов и банальной открытчатой «позитивности». Композиция должна развиваться, а не просто выполнять формальные требования. Эти критерии пока **не гарантированы** генератором.

### Математика текущего прототипа

В `train` для целевой правки выбирается `t ∈ [0.05, 1]`, маскируется `ceil(tN)` содержательных токенов; разделители строк, строф и условие видны. Модель предсказывает исходные токены на замаскированных позициях; loss — средняя cross-entropy по ним. Часть примеров видит тему **без** черновика (`draft_dropout`), чтобы была возможна генерация с нуля. В `sample` все содержательные позиции шаблона закрыты, на каждом шаге модель оценивает их и фиксирует часть наиболее уверенных; сильные строки можно оставить немаскированными через `--lock-lines`. Это реальная архитектура absorbing-mask diffusion, но пока **прототип**, не доказательство новизны или качества. В основе — идея [Simple and Effective Masked Diffusion Language Models](https://proceedings.neurips.cc/paper_files/paper/2024/hash/eb0b13cc515724ab8015bc978fdde0ad-Abstract-Conference.html); [русская модель MLM](https://huggingface.co/ai-forever/ruBert-base).

## 3. Данные, приватность и проверка качества

Формат локального JSONL: `{"topic":"...","draft":"...","revision":"...","accepted":true}`. `export-trace` извлекает пары из старого Ollama `trace.json`, но ставит `accepted: null`; человек должен решить, улучшилась ли версия. По умолчанию обучение допускает **только `accepted: true`**. `--include-unreviewed` существует только для технических экспериментов. Нельзя объявлять автоматическую правку удачной по факту её создания.

В публичном репозитории **нет** личных стихов из исходного handoff, датасета, записей или весов. `data/`, `eval/`, `checkpoints/`, `output/` и `*.jsonl` исключены из Git. Не публиковать личное стихотворение автора для мамы и другие частные тексты; пользователь говорил, что не хочет распространять их. Не использовать их для обучения без отдельного явного решения автора. Не интерпретировать литературные образы как сведения о его нынешнем состоянии.

Для честной оценки нужны отложенные темы и слепые человеческие пары: диффузия против одношаговой и отредактированной Ollama, те же задания, фиксированные seed/настройки, шкалы ритма, образности, цельности, общего впечатления; регрессии и ничьи сохранять. `blind_eval.py` даёт протокол, **результатов пока нет**.

## 4. Проверенное и непроверенное

- Первоначальный MVP восстановлен из исходников в приложенном старом handoff. Исторические 8 тестов прошли; после фонетики и аудио было 14, после масочной диффузии — 17.
- На нынешней вехе локально обнаружено **19 тестов: 18 прошли, 1 пропущен**, поскольку в Linux окружении нет PyTorch/Transformers. Компиляция Python прошла. Тесты покрывают маскирование, границы строк, закрепление строк, обратное раскрытие, отбор одобренных правок, WAV с известным тоном/паузой, имитацию Ollama и A/B рандомизацию.
- PyTorch smoke test с настоящим backward/optimizer на tiny BERT **прошёл** в [GitHub Actions run 42542742339](https://github.com/aisarus/Poetry/actions/runs/42542742339): зависимости установлены, шаг тестов завершился успешно. Он **не** скачивает большую русскую модель.
- В этом окружении **нет NVIDIA GPU**, PyTorch, Transformers, скачанных весов и набора одобренных пар. HTTPS-запросы к PyPI и Hugging Face завершились таймаутом. **Не было** fine-tuning, генерации обученной диффузионной моделью, реального Windows SAPI или человеческой оценки качества. Нельзя говорить «модель уже пишет крутые стихи».

## 5. Как продолжить без повторения сделанного

1. Код `train/sample` большой модели ещё не проверялся в рабочем окружении; запустить минимальный настоящий train/sample на GPU, диагностировать OOM и скорость. На пользовательском ПК ранее сообщалась NVIDIA RTX 5070 Ti 12 GB, но **доступность этой машины из текущей сессии не установлена**.
2. Подготовить множество **ручных принятых** пар правок с правами на тексты; хранить локально. Отделить обучающие темы и авторов от тестовых. Небольшой набор траекторий сам по себе не обучит 178M модель писать сильную поэзию; нужен эксперимент с регуляризацией и объёмом данных.
3. Запустить `train` и `sample`, сохранить параметры, версии данных, время, loss, примеры и ошибки. Сравнить с Ollama baseline на отложенных темах слепым протоколом, не выдавать формальные метрики рифмы за художественную оценку.
4. Интегрировать слух в **сам** диффузионный цикл: измерять чтение после итерации, выравнивать аудио и текст, локально ремаскировать проблемные места, защищать сильные строки и останавливать правку при регрессии. Текущий аудиоанализатор только выдаёт ограниченные числовые наблюдения в Ollama baseline.
5. Расширить русский словарь ударений и использовать проверенный G2P; омографы и ошибки TTS помечать неопределёнными. Приоритет качества стихов выше формального совпадения схемы.

### Команды на машине с GPU

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements-diffusion.txt
python -m unittest discover -v
python masked_diffusion.py export-trace --trace output\RUN_ID\trace.json --topic "Тема" --out data\pairs.jsonl
# Просмотреть pairs.jsonl, принять только реально улучшенные пары (accepted: true)
python masked_diffusion.py train --data data\pairs.jsonl --out checkpoints\poetry-v1 --epochs 3 --max-length 256 --accumulation 8
python masked_diffusion.py sample --checkpoint checkpoints\poetry-v1 --topic "Праздник маленькой победы" --stanzas 2 --steps 16 --out output\diffusion.txt
```

Оценка: составить `eval/candidates.jsonl` с полями `topic_id`, `topic`, `baseline`, `diffusion`; `python blind_eval.py prepare --candidates eval/candidates.jsonl --out eval/round1`; оценщику дать **только** `ballot.jsonl`, заполнить `preferred`, затем `python blind_eval.py score --ballot eval/round1/ballot.jsonl --key eval/round1/key.json --out eval/round1/report.json`.
