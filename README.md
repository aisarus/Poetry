# Poetry Lab — исследование диффузионной поэзии

**Главная цель — обучить модель, которая создаёт сильную русскую поэзию последовательным уточнением всего текста.** В репозитории два слоя: `masked_diffusion.py` — обучаемый генератор с дискретной масочной диффузией; `poetry_lab.py` — прежний Ollama baseline, сохраняющий правки и измеряющий звучание. Качество диффузионной модели пока не доказано: для него нужны отобранные данные, обучение и слепая оценка людьми.

## Диффузионный генератор

Базовая русская модель с MLM головой — `ai-forever/ruBert-base` (~178 млн параметров). На обучении выбирается случайная доля токенов исправленного стихотворения, они заменяются `[MASK]`, и модель предсказывает исходные токены по оставшимся словам, теме и исходному черновику. Маски с разными долями шума создают смесь задач денойзинга. На генерации все позиции строк сначала закрыты, а затем открываются несколькими шагами по уверенности модели. Строки черновика можно закрепить. Это **masked discrete diffusion**, а не вызов Ollama с просьбой «переписать» и не готовая художественная модель. Основа метода: [Simple and Effective Masked Diffusion Language Models](https://proceedings.neurips.cc/paper_files/paper/2024/hash/eb0b13cc515724ab8015bc978fdde0ad-Abstract-Conference.html). [Карточка русской MLM модели](https://huggingface.co/ai-forever/ruBert-base).

Отдельное окружение Python с PyTorch и Transformers:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements-diffusion.txt
```

Сначала экспортируйте пары из локального прогона Ollama (файл остаётся на вашем компьютере):

```powershell
python masked_diffusion.py export-trace --trace output\RUN_ID\trace.json --topic "Тема прогона" --out data\pairs.jsonl
```

В JSONL каждая строка содержит `topic`, `draft`, `revision`, `accepted`. Экспорт ставит `accepted: null`: **прочитайте обе версии и поставьте `true` только там, где правка действительно улучшила стих**. Можно составить свои пары напрямую. Личные стихи и веса моделей не коммитить; `data/`, `checkpoints/` и `*.jsonl` исключены из Git. Не используйте чужие тексты без прав и согласия. Без размеченных удачных правок обучение остановится. Для чисто технического эксперимента есть `--include-unreviewed`, но это риск учить модель на ухудшениях.

```powershell
python masked_diffusion.py train --data data\pairs.jsonl --out checkpoints\poetry-v1 --epochs 3 --max-length 256 --accumulation 8
python masked_diffusion.py sample --checkpoint checkpoints\poetry-v1 --topic "Праздник маленькой победы" --stanzas 2 --steps 16 --out output\diffusion.txt
python masked_diffusion.py sample --checkpoint checkpoints\poetry-v1 --topic "Праздник" --draft-file my_poem.txt --lock-lines 1,4 --out output\revision.txt
```

Первое скачивание базовой модели требует сети. При запуске используется GPU CUDA, если он доступен; иначе CPU. На GPU включается gradient checkpointing. `max-length` ограничивает сумму темы, черновика и стихотворения; слишком длинные пары пропускаются со счётчиком. Длина генерируемых строк задаётся **числом токенов**, а не слогов; короткая четвёртая строка пока лишь структурный шаблон. Если данных мало, обучение на нескольких парах даст переобучение и слабые стихи. Измерители звука и фонетики пока подключены к Ollama baseline, а не к функции отбора токенов диффузионной модели.

## Предыдущий Ollama baseline

### Требования

- Windows 10/11, Python 3.10+.
- Установленный и запущенный Ollama, локально загруженная модель, например `qwen2.5:7b`.
- Для синтеза речи: Windows SAPI, желательно установленный русский голос. Без русского голоса качество чтения будет низким.
- В Python **нет дополнительных зависимостей**. После загрузки локальной модели сеть не требуется.

## Быстрый старт (PowerShell)

```powershell
ollama pull qwen2.5:7b
python poetry_lab.py --topic "Тёплая ирония случайной встречи" --stanzas 5 --rounds 2 --speak
```

Работа с уже написанным текстом:

```powershell
python poetry_lab.py --file my_poem.txt --rounds 2 --speak
```

Только технический анализ, без LLM:

```powershell
python poetry_lab.py --file my_poem.txt --analyze-only
```

Цикл с измерением реального WAV на каждой версии (нужен русский голос Windows SAPI):

```powershell
python poetry_lab.py --file my_poem.txt --rounds 1 --audio-feedback
```

При необходимости: `--model <имя>`, `--schemes ABBA,ABAB,AABB`, `--out output` и `--url http://127.0.0.1:11434`.

## Выход

В папке `output/<timestamp>/`:

- `poem_00.txt`, `poem_01.txt` и т.д. — версии произведения;
- `critique_00.txt` и т.д. — разборы редактора;
- `metrics_00.json` — машинная разметка;
- `trace.json` — полная история итераций для будущего датасета;
- `final.txt` — итоговая версия;
- `final.wav` — озвучивание через Windows SAPI, если передан `--speak`.
- При `--audio-feedback`: `reading_00.wav` и `audio_00/line_*.wav` для каждого этапа, а также `audio_metrics_00.json`; данные попадают в `trace.json` и в запрос критику **до** редакторской правки. Для финальной версии также сохраняется чтение. `--speak` дополнительно создаёт `final.wav` из уже записанного чтения.

**Осторожно с метриками:** `syllables` считает буквы-гласные, а не реальные метрические стопы и ударения. `shared_final_vowels` сравнивает письменные гласные концовок слов; это **не** проверка фонемной рифмы. Аудиоанализ измеряет длительность, паузы по энергии и грубую периодичность голоса в настоящем PCM WAV. Строки синтезируются отдельно, поэтому их просодия может отличаться от цельного чтения. Модель получает числовую сводку, а не слушает запись; ударения голоса, смысл и художественное качество автоматически не проверяются.

## Ударения и слуховые подсказки

`phonetic_lines` содержит рисунок слогов (`1` — ударный, `0` — безударный, `?` — неизвестное ударение). Разметка опирается на небольшой встроенный словарь, букву `ё`, односложные слова и явно проставленные ударения. Свой словарь можно передать через `--stress-lexicon stresses.txt`; в UTF-8 файле пишите формы `кара́мель`, по одной или несколько на строку. Для омографов можно поставить ударение прямо в тексте (`за́мок` / `замо́к`).

Поле `rhyme_hints[].phonetic` сравнивает приближённое звучание от ударной гласной. `unavailable` означает, что ударение неизвестно. `candidate` — лишь подсказка: это пока не полный G2P, словарь не распознаёт контекст и не доказывает качество рифмы или метра. Личные тексты и локальные прогоны храните вне публичного репозитория.

## Как сделать корректный эксперимент

Для 20–50 отдельных тем сравнить черновик Ollama (`rounds=0`), его редактуру (`rounds=1/2`) и образец обученной диффузионной модели при сопоставимом задании. Не оценивать на темах и парах из обучения; зафиксировать seed и параметры. Проводить слепую оценку: выразительность, фонетика, образность, общая ценность, индивидуальный голос. Не показывать оценщику способ генерации. Обязательно проверять ухудшения: редактура и дополнительные проходы могут портить лучшие строки.

`blind_eval.py` скрывает принадлежность вариантов A/B и считает предпочтения. Создайте локальный JSONL с отдельной строкой на тему: `{"topic_id":"t01","topic":"...","baseline":"...","diffusion":"..."}`. Затем:

```powershell
python blind_eval.py prepare --candidates eval\candidates.jsonl --out eval\round1 --seed 42
# Передайте оценщику только eval\round1\ballot.jsonl. key.json не показывать.
# Оценщик заполняет preferred: "A", "B" или "tie" для каждой строки.
python blind_eval.py score --ballot eval\round1\ballot.jsonl --key eval\round1\key.json --out eval\round1\report.json
```

Отчёт содержит число побед, ничьих, долю побед диффузионной модели среди решённых пар и интервал Вилсона 95%. Одинаковые темы, пустые и идентичные варианты отвергаются. Папка `eval/` не попадает в Git; предпочтения должны быть человеческими, а не сгенерированными теми же моделями.

## Следующий этап

1. Реально обучить диффузионный прототип на качественных одобренных траекториях и оценить генерацию против baseline. Прямой запуск весов здесь ещё не проведён.
2. Подключить фонетику и измеренный аудиосигнал к выбору локальных участков для повторного маскирования, сохраняя удачные строки.
3. Расширить словарь ударений, проверить русский G2P и Windows SAPI, выровнять звук с текстом. STT-транскрипция **не** заменяет оценки аудиоритма.
4. Собирать человеческие попарные предпочтения с пометками «исправлено/ухудшено» и использовать их для ранней остановки.
