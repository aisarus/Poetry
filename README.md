# Poetry Lab — локальный исследовательский MVP

Это **не диффузионная модель** и не система объективной оценки поэзии. Это воспроизводимый **генератор → критик → редактор**, который сохраняет всю историю правок и грубую фонетическую диагностику. Он позволяет проверить гипотезу, что итеративная редактура улучшает результат по сравнению с одной генерацией.

## Требования

- Windows 10/11, Python 3.10+.
- Установленный и запущенный Ollama, локально загруженная модель, например `qwen2.5:7b`.
- Для синтеза речи: Windows SAPI, желательно установленный русский голос. Без русского голоса качество чтения будет низким.
- В Python **нет дополнительных зависимостей**. После загрузки локальной модели сеть не требуется.

## Быстрый старт (PowerShell)

```powershell
ollama pull qwen2.5:7b
python poetry_lab.py --topic "Тёплая ирония случайной встречи" --stanzas 5 --rounds 2 --speak
```

Работа с уже написанным текстом:

```powershell
python poetry_lab.py --file my_poem.txt --rounds 2 --speak
```

Только технический анализ, без LLM:

```powershell
python poetry_lab.py --file my_poem.txt --analyze-only
```

Цикл с измерением реального WAV на каждой версии (нужен русский голос Windows SAPI):

```powershell
python poetry_lab.py --file my_poem.txt --rounds 1 --audio-feedback
```

При необходимости: `--model <имя>`, `--schemes ABBA,ABAB,AABB`, `--out output` и `--url http://127.0.0.1:11434`.

## Выход

В папке `output/<timestamp>/`:

- `poem_00.txt`, `poem_01.txt` и т.д. — версии произведения;
- `critique_00.txt` и т.д. — разборы редактора;
- `metrics_00.json` — машинная разметка;
- `trace.json` — полная история итераций для будущего датасета;
- `final.txt` — итоговая версия;
- `final.wav` — озвучивание через Windows SAPI, если передан `--speak`.
- При `--audio-feedback`: `reading_00.wav` и `audio_00/line_*.wav` для каждого этапа, а также `audio_metrics_00.json`; данные попадают в `trace.json` и в запрос критику **до** редакторской правки. Для финальной версии также сохраняется чтение. `--speak` дополнительно создаёт `final.wav` из уже записанного чтения.

**Осторожно с метриками:** `syllables` считает буквы-гласные, а не реальные метрические стопы и ударения. `shared_final_vowels` сравнивает письменные гласные концовок слов; это **не** проверка фонемной рифмы. Аудиоанализ измеряет длительность, паузы по энергии и грубую периодичность голоса в настоящем PCM WAV. Строки синтезируются отдельно, поэтому их просодия может отличаться от цельного чтения. Модель получает числовую сводку, а не слушает запись; ударения голоса, смысл и художественное качество автоматически не проверяются.

## Ударения и слуховые подсказки

`phonetic_lines` содержит рисунок слогов (`1` — ударный, `0` — безударный, `?` — неизвестное ударение). Разметка опирается на небольшой встроенный словарь, букву `ё`, односложные слова и явно проставленные ударения. Свой словарь можно передать через `--stress-lexicon stresses.txt`; в UTF-8 файле пишите формы `кара́мель`, по одной или несколько на строку. Для омографов можно поставить ударение прямо в тексте (`за́мок` / `замо́к`).

Поле `rhyme_hints[].phonetic` сравнивает приближённое звучание от ударной гласной. `unavailable` означает, что ударение неизвестно. `candidate` — лишь подсказка: это пока не полный G2P, словарь не распознаёт контекст и не доказывает качество рифмы или метра. Личные тексты и локальные прогоны храните вне публичного репозитория.

## Как сделать корректный эксперимент

Для 20–50 разных тем получить `rounds=0` и `rounds=2` при одинаковых модели и заданиях (впоследствии добавим фиксированные seed и отдельные выборки). Проводить слепую оценку парами: выразительность, фонетика, образность, общая ценность, индивидуальный голос. Не показывать оценщику номер итерации. Обязательно проверять ухудшения: редактор нередко портит лучшие строки.

## Следующий этап

1. Расширить словарь ударений и подключить проверенный русский G2P: текущая разметка неполная.
2. Проверить Windows SAPI с русским голосом на машине пользователя и сопоставить цельное чтение с записью отдельных строк. Улучшить TTS, разметку слоговых акцентов и пауз.
3. Выравнивать звук и текст, сравнивать ожидаемые и фактические ударения. STT-транскрипция **не** заменяет оценки аудиоритма.
4. Человеческие попарные предпочтения и dataset правок с пометками «исправлено/ухудшено».
5. После базового сравнения — эксперимент с masked diffusion / non-autoregressive editing.
